# 前処理を行う理由

## 1. なぜ元データをそのままモデルへ渡さないのか

WiSig ManyRx は、送信機、受信機、日、表現が何重にも入れ子になった pickle です。モデルごとに別々の読み方を書くと、あるモデルだけ別の日を使ったり、ラベルの番号がずれたりする恐れがあります。

一度だけ共通形式へ変換し、5手法が同じファイルを読むようにすると、比較しやすくなります。

## 2. pickle を先に検査する理由

pickle は単なる数字の箱ではなく、読み込み時に Python の処理を復元できる形式です。そのため、出所不明の pickle を無条件で開くのは危険です。

`01_inspect_wisig.py` と `02_prepare_wisig.py` は、最初に pickle の全命令を走査します。NumPy 配列の復元に必要な決められた命令以外があれば停止します。

この検査は危険を減らしますが、数学的に完全な安全証明ではありません。必ず公式 WiSig 配布元から取得し、可能なら SHA-256 も照合します。

## 3. グループごとにファイルを分ける理由

1つの巨大ファイルに全部入れると、一部だけ使いたい場合でも全体を開く必要があります。送信機・受信機・日ごとに分ければ、必要なグループだけ読めます。

また、学習と評価を分けるときに、同じ環境の信号を誤って両方へ混ぜにくくなります。

## 4. この段階で正規化しない理由

標準化に使う平均や分散を評価データから計算すると、評価データの情報が学習側へ漏れます。これをデータリークと呼びます。

そのため、ここでは配列の形と数の型をそろえるだけにします。平均・分散などは、分割を固定した後、学習データだけで計算します。

## 5. equalized と unprocessed

- `unprocessed`: 通信路の影響がより残った表現
- `equalized`: 推定した通信路の影響を一部補正した表現

equalized が常に正解とは限りません。補正によって端末固有の特徴も変わる可能性があります。ただし最初から両方を混ぜると原因が分かりにくいため、主実験で1つを固定し、もう1つは追加実験として比べます。

## 6. 変換後に再検査する理由

コピー中の中断、空き容量不足、プログラムの間違いがあると、ファイルが欠けたり壊れたりします。`03_verify_prepared_data.py` は目次と実ファイルを1件ずつ照合します。

検査が成功した結果には `verification_passed: true` が記録されます。これを確認してから学習段階へ進みます。
