# SupCon + Prototype のやさしい説明

## 何をする方法か

SupCon は、同じ端末の特徴を近づけ、別の端末の特徴を遠ざける学習です。普通の分類では最終的な正解だけを教えますが、SupCon では特徴空間の並び方も直接教えます。

## たとえ

机の上に写真を並べるとします。同じ人の写真は同じ箱の近くへ、別の人の写真は別の箱へ置きます。明るさや向きが変わった写真でも同じ人なら近くへ置けるように練習します。

RFF では「人」が端末、「写真」が I/Q 信号です。

## なぜ2つの view を作るのか

同じ信号へ小さな変化を加えた2つを作り、どちらも同じ端末の特徴になるようにします。候補は小さな位相回転、時間ずらし、gain 変化、弱い雑音です。

ただし、強すぎる変化は端末固有の特徴を壊します。変化の範囲は validation で決め、全手法との公平性も記録します。

## 学習時の入力と出力

- 入力: 既知端末信号から作った2 view と端末ラベル
- encoder 出力: 将来の判定に使う特徴
- projection head 出力: SupCon loss の計算専用特徴
- loss: 同じ端末を近づけ、違う端末を遠ざける supervised contrastive loss

学習後、projection head は捨て、encoder の特徴を使います。

## prototype 判定

学習データの encoder 特徴を端末ごとに平均し、prototype を作ります。新しい特徴がどの prototype にも近くなければ unknown とします。

距離を cosine にするか Euclidean にするか、クラス共通しきい値かクラス別しきい値かは、実験前に候補を固定します。

## 限界

SupCon は1つの batch 内に同じ端末の positive が必要です。batch の作り方で結果が大きく変わります。また、データ拡張が現実の変化を正しく表していなければ、必要な指紋まで消す可能性があります。
