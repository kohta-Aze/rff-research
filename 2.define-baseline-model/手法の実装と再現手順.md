## 共通骨格と学習

- 入力はローダーの `[B,256,2]` をPyTorchの `float32[B,2,256]` へ変換。
- 実数Conv1d: channel 32→64→128、kernel 7・5・3、各段BN・ReLU・MaxPool 2。4096→128のReLU特徴、分類用dropout 0.2、既知6クラスの線形分類器。
- 新規学習はAdam、学習率0.001、weight decay 0、元信号batch 64、上限50 epoch、改善なし10 epochで停止。
- MSP・SupCon・MTPLは同じseedの初期encoderから新規学習。Cosine・OpenMaxはMSPの同一学習済みCNNを固定して使用し、独立に再学習しない。
- モデル選択は既知validationだけ。閾値は既知＋調整用未知validationで `0.5 × (CCR + 1 - FAR)` 最大化、同点は高い閾値。test読込前に確定。
- 各手法でloss・拡張・head・checkpoint選択・調整自由度・実行時間が異なる。loss単独の因果比較や同一計算予算の比較ではない。

| 手法 | 学習・checkpoint選択 | 推論の既知候補・主スコア |
|---|---|---|
| MSP | 既知CE、既知validation分類器CE最小、拡張なし | 最大logitクラス・最大softmax確率 |
| Cosine | 固定MSP、training限定prototype | 最大cosineのクラス・類似度 |
| OpenMax | 固定MSP、正解training限定Weibull校正 | 補正後既知最大クラス・符号付き確率 |
| SupCon | 2 viewのSupCon、既知validation prototype CE最小 | 投影前特徴の最大cosine・類似度 |
| MTPL | 分類＋復元＋prototype、既知validation分類器CE最小、拡張なし | 学習済みprototypeへの最小距離クラス・GPD裾確率 |

## MSPとCosine Prototype

- MSPはsoftmax値が低ければ未知として拒否する単純基準。softmaxは既知クラス内の配分であり、未知端末でも高い値になり得る。
- Cosineのprototypeはtrainingの128次元生特徴をクラス別に平均してからL2正規化。特徴ごとの正規化後平均とは異なる。平均・類似度はfloat64。
- Cosineの推論は最大類似度の端末候補を閾値と比較。代表点1個でクラスを表し、多峰性の影響は別途検証が必要。
- 保存したImproved Prototype Learning論文は問題設定の根拠。consistency regularization・online label smoothingは未実装であり、同論文の再現とはしない。

## 採用ベースライン: OpenMax

- 既知クラス中心から遠いtraining例の裾をWeibullで表し、既知activationの一部を未知activationへ再配分する。
- activationは6クラスlogitsの単一チャネル。128次元CNN特徴ではない。正しく分類した既知trainingのみでクラス中心・裾をfit。
- 距離は `eucos = Euclidean / 200 + cosine distance`。公式libMRの `fit_high` を使用。
- tail 20/50/100×alpha 1/3/6の9候補を事前定義。validationのbalanced評価で候補・正の閾値を選択、候補間の同点は設定順、閾値の同点は高い値。
- 順位重みとWeibull確率で上位alphaクラスを補正し、差分総和を未知activationへ移す。負のlogitsを切り捨てない。
- 既知6＋未知1のsoftmaxを計算。未知確率が既知最大確率以上なら拒否、それ以外は既知最大確率を閾値と比較。
- 評価スコアは既知勝者なら最大既知確率、未知勝者なら負の未知確率。正の運用閾値で上記の受入制約を保持。
- AUROC・OSCRは負スコアを含む全域を掃引し、未知勝者を受入れる仮想的な領域も含む。面積と運用閾値の性能を区別する。
- 画像用原論文をI/Qへ適用した比較実装。受信条件で裾分布が変わる可能性と調整自由度を記録し、原論文の公開スコアをWiSigの期待値にしない。

## SupCon＋Prototype

- 同じ端末の特徴を近づけ、異なる端末を離す対照学習。論文式(2)の全viewをanchorとし、自己対を除外、同クラスの他viewをpositiveにする。
- 64信号から独立な2 viewを作り、CNN入力は128信号。同じ元信号の別viewでpositiveを保証。batchはseed付きランダム順で既知trainingを1回ずつ使用。
- projectionは128→128→128、Linear・ReLU・Linear・L2正規化。温度・基準温度0.07。分類headとencoder dropoutは使用しない。
- 拡張は位相±10度・AWGN 30 dB・RMS再正規化、拡張seedは学習seed＋1。時間ずらし・gain変更なし、validation・testは無拡張。
- 各epochの無拡張trainingだけでprototypeを作り、既知validationの `cross_entropy(cosine / 0.07)` 最小を選択。
- 推論はprojectionを破棄し、128次元encoder特徴をCosineと同じ平均・L2正規化・閾値規則で使用。画像用拡張や原論文のlinear probeではない。

## MTPL＋EVT比較版

- 分類・復元・prototype集約を同時学習。prototypeは6×128の学習可能パラメータ、Gaussian標準偏差0.01で初期化。学習後も平均へ置換せず、L2正規化しない。
- lossは `CE + 0.1 × 復元二乗誤差総和 + 0.05 × 正解prototype二乗距離` のサンプル平均。座標平均のMSEではない。
- decoderはLinear 128→4096・ReLU・128×32へreshape、ConvTranspose1dで64→32→2 channel、kernel 4・stride 2・padding 1、途中BN・ReLU、出力線形。
- 原論文のloss記号説明には入れ替わりがあり、式(4)・(5)とAlgorithm 1の定義を採用。重みは固定値であり、testから選ばない。
- 原論文の複素CNN・4800点入力・decoder・初期化・100 epoch・batch 128・schedulerとは異なる共通CNN比較版。
- 選択モデルのtraining全件について正解prototypeへの二乗距離を集約。誤分類trainingも含め、validation・testはfitに使用しない。
- 全体0.9 quantileをlinear補間で求め、境界omega超過分をSciPy `genpareto.fit(..., floc=0)` でMLE推定。原論文Algorithm 2の0.9を採用し、5.2節の0.1とは区別。
- 推論は最小二乗距離とargminの端末候補。classifier・decoderは未知判定に使用しない。
- omega内側の主スコアは1、外側は条件付きGPD survival probability。既知の事後確率ではない。運用deltaを `0 < delta <= 1` に限定し、内側は常に受入れる。
- 主deltaは共通validation目的で選択。固定delta 0.01と負の最小距離の順位評価はtest前に定義した補助評価。主スコアと混同せず、test後の置き換えはしない。

## 再現手順

- 作業場所はリポジトリルート。元ManyRxデータと[前処理](00_common/data_preprocessing/README.md)が必要。数値JSONだけでは再学習できない。
- 確認環境はWindows、Python 3.13.14、PyTorch 2.7.0、CPU 4スレッド。全パッケージの実測版は結果JSONの `runtime`。別OS・デバイスで同一値となることは未確認。
- 仮想環境がない場合はPython 3.13で `python -m venv 2.define-baseline-model/00_common/data_preprocessing/venv` を実行してから前処理・依存導入へ進む。macOSのPythonパスは `venv/bin/python` に置換。
- 共通依存に加えOpenMaxにはC++拡張libMRが必要。WindowsはMSVC、macOSはC++コンパイラ。Cythonを先に導入し、libMRはビルド分離を無効化。

```powershell
$base = '2.define-baseline-model'
$python = "$base/00_common/data_preprocessing/venv/Scripts/python.exe"
& $python -m pip install -r "$base/00_common/modeling/requirements.txt"
& $python -m pip install Cython==3.1.3
& $python -m pip install libmr==0.1.9 --no-build-isolation
```

- 既存結果を上書きせず、別名の出力を各比較対象へ明示的に渡す。以下の出力先が既に存在する場合は名前を変更。

```powershell
$name = 'reproduction_20261006_fold00_seed42'
$msp = "$base/01_cnn_msp/output/$name"
$cosine = "$base/02_cnn_cosine_prototype/output/$name"
$openmax = "$base/03_cnn_openmax/output/$name"
$supcon = "$base/04_supcon_prototype/output/$name"
$mtpl = "$base/05_mtpl_evt/output/$name"
& $python "$base/01_cnn_msp/scripts/run_experiment.py" --fold 0 --seed 42 --output $msp
& $python "$base/02_cnn_cosine_prototype/scripts/run_prototype_experiment.py" --source-run $msp --output $cosine
& $python "$base/03_cnn_openmax/scripts/run_openmax_experiment.py" --source-run $msp --prototype-run $cosine --output $openmax
& $python "$base/04_supcon_prototype/scripts/run_supcon_experiment.py" --reference-run $msp --prototype-run $cosine --openmax-run $openmax --output $supcon
& $python "$base/05_mtpl_evt/scripts/run_mtpl_experiment.py" --reference-run $msp --prototype-run $cosine --openmax-run $openmax --supcon-run $supcon --output $mtpl
```

- 動作確認は別出力先へ `--validation-only`。新規学習手法は `--max-epochs 1` も指定可能。動作確認を主評価結果に混ぜず、比較元は完了した主実験を使用。
- fold・seedの変更はMSPに指定し、後続はそのrunを参照。全反復の自動実行は未実装。
- MSPの `--supplemental` は全32 Rx等の追加評価。初回比較は主評価だけで、後続4手法の同条件追加評価は別途実装が必要。

## 出力と検証

- 実行スクリプトは共通NPZ・foldを参照し、独自に再分割しない。失敗時は `run.json` に原因を記録して停止。
- 各 `output/<run>/` の `run.json`・`config.json`・`fold_XX.json`・`source_snapshot/` は条件・環境・入力参照・実行時コード。
- `best_model.pt` または `cnn_model.pt`、`history.csv`、prototype・Weibull/GPD校正・`threshold.json` は再現に必要な生成物。
- `metrics.json/csv`、信号別 `*_predictions.csv`・`*.npz`、Tx/Rx別 `*_subgroups.csv`、OSCR曲線・混同行列を保存。既知のみ・未知のみの部分集合の面積指標はnull。
- OpenMaxは `validation_candidates.csv`、MTPLは `paper_delta_metrics.json/csv` も保存。機械可読のGit用結果JSONは指標・条件の抜粋で、波形・信号別予測・重みを含まない。
- 初回検証の記録: 入力参照・ハッシュ・状態不変、training限定校正、予測・混同行列・AUROC・OSCRを独立照合。SupCon・MTPLの初期encoderと1 epoch目の重みの再現、loss・GPD支持域も確認。
