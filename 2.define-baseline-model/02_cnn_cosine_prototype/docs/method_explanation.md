# CNN + Cosine Prototype のやさしい説明

## prototype とは

同じ端末の特徴ベクトルを平均して作る「代表選手」です。端末Aの特徴がたくさんあるなら、それらの中心を端末Aの prototype とします。

## cosine similarity とは

2本の矢印の向きがどれくらい似ているかを `-1` から `1` で表します。`1` に近いほど同じ向きです。ベクトルの長さより向きを重視するため、信号の大きさが変わる影響を少し受けにくい可能性があります。

## 何を目的にするか

既知端末の特徴を「端末ごとの中心」として表し、どの中心からも遠い信号を未知として拒否します。

## prototype を作る入力と出力

- 入力: 学習済み CNN、既知端末の training 信号と端末ラベル
- 処理: CNN で特徴を作り、端末ごとに平均し、長さ1へ正規化
- 出力: `[known_class_count, embedding_dim]` の prototype 行列

prototype の作成に validation や test 信号は使いません。

## 推論の入力と出力

1. 新しい信号から特徴ベクトルを作る。
2. 特徴を長さ1へ正規化する。
3. 全 prototype との cosine similarity を計算する。
4. 最大 similarity の端末を候補にする。
5. 最大 similarity がしきい値未満なら `unknown` にする。

## 限界

1クラスを1つの中心だけで表すため、同じ端末でも受信機や日によって特徴が複数のかたまりになる場合に弱い可能性があります。また、cosine を選ぶこと自体は今回の比較用設計であり、保存した IPL 論文そのままの再現ではありません。
