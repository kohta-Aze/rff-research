# 認証試行の履歴から不審候補を記録する実験

- 目的: 固定したCNN＋OpenMaxに履歴監視を加え、見逃しと正常端末の誤検知を測る。
- 登録IDへのなりすまし認証: OpenMaxが受け入れ、かつ予測IDと申告IDが一致した場合だけ成功。
- 不審候補は受信側の追跡用識別子に紐付ける。名乗られた登録IDを犯人として登録しない。
- 出力は要確認リスト。遮断した場合の数値は保存データ上の比較で、実際の認証結果を変更しない。

## 初回の観測

- 全開始IDを含む疑似総当たり192履歴は全て要確認となったが、遮断を仮定しても30履歴で掲載前に成功があった。追跡用識別子を毎回変えると検知は0／192履歴。
- 正常な同日履歴は4／96、日を変更した正常履歴は3〜5／96が要確認となった。誤検知を含むため、そのまま自動遮断する根拠にはしない。
- 初見の過去日録音は、同じ入力の正常信号と判定が一致した。固定IDの最悪の組は通過率73.4％から71.7％で、特定IDへのなりすましは解消していない。

- 単体検証14件と48,240試行行の再集計を確認。元のOpenMaxの全4日分の判定は一致した。

## 監視ルール

- 60秒以内に3種類以上の登録IDを名乗ると`id_sweep`。
- 直近10回かつ60秒以内で、登録特徴からのずれが3回以上なら`reference_mismatch`、特徴の急変が3回以上なら`feature_changes`。
- 同じ追跡用識別子で、正規化後の保存波形が60秒以内に3回以上完全一致すると`exact_waveform_reuse`。
- 該当時点から300秒間を要確認とする。新たな該当で延長。監視は未来の試行を参照しない。
- 128次元のCNN特徴を長さ1にそろえ、端末ごとの平均特徴との距離を比較する。参照値は既知training、距離の上限は同日既知validationの99％点。急変の上限も同日既知validationだけで決める。
- 元のCNN・OpenMax・認証しきい値は固定。評価用未知Txや別日の信号でルールを調整しない。

## 比較する条件と限界

- 正常: 同日、途中で日を変更、途中で受信機を変更。後二者も正常として誤検知を数える。
- 疑似攻撃: 未登録端末がIDを固定／順番に変更、既知波形への位相回転と周波数ずれ相当の加工、保存波形の完全一致での繰返し、初見の過去日録音。
- 未登録Tx×全申告IDの固定ID比較も保存する。ID切替は全6種類の開始IDを比較する。総平均に加え、端末と申告IDの組ごとの通過率を確認する。
- 疑似攻撃は学習と同日のtestを使う。別日・受信機変更は正常端末の誤検知を調べる対照条件。
- WiSigに実際の認証時刻・試行履歴はない。SHA-256順の信号を1秒間隔で並べた疑似履歴で、正常時の運用頻度や検知までの実時間を実証するものではない。
- 同じTx×Rxの信号を受信側の識別子で追跡できると仮定する。真のTxを使うのは履歴の構成と集計だけで、監視関数には渡さない。ID切替中の送信元の追跡方法は未実装。追跡識別子を毎回変える回避条件も比較する。
- 過去日の初見録音と同じ入力の正常信号を比較する。波形から録音の古さ・送信場所・悪意を断定できない。別の受信機への変更は場所変更そのものの実験ではない。
- 保存波形の完全一致は、再送信後に雑音・通信路・受信機の影響を受ける実際の電波リプレイと異なる。最初の成功や初見の録音を防げるとは限らない。
- 録音再送への対策には、毎回異なる要求と応答の結び付け等による新しさの確認も必要。[NISTのリプレイ耐性の説明](https://pages.nist.gov/800-63-4/sp800-63b.html)。この通信手順は本実験の対象外。
- fold 0・seed 42の既存データによる探索。信号・疑似履歴は同じ収録を共有し、独立した実攻撃試行数として扱わない。

## 実行

- リポジトリ直下のPowerShellで実行。既存の前処理済みWiSigと完了済みOpenMax出力を使う。環境の準備は[親README](../README.md)を参照。

```powershell
$python = '2.define-baseline-model/00_common/data_preprocessing/venv/Scripts/python.exe'
$monitor = '2.define-baseline-model/06_suspicious_attempt_monitor'
& $python -m unittest discover -s "$monitor/tests" -v
& $python "$monitor/scripts/run_monitor_experiment.py"
```

- `--source-run`で完了済みOpenMaxの出力を指定できる。`--config`で条件、`--output`で未作成の出力先を指定する。
- `run.json`が`completed`で、全日の`baseline_decisions_identical`が`true`であることを確認する。
- `summary.csv`: 条件別の要確認率・元の通過率・リスト掲載後に遮断した場合の通過率。正常条件の要確認率は誤検知。
- `streams.csv`: 履歴別の初回掲載位置・一度でも通過したか。後からリスト掲載されても先行成功は消さない。
- `watchlist.csv`: 要確認の追跡識別子・掲載時点・理由。掲載後の経過は`attempts.csv`の`watch_until`を参照。
- `unknown_claim_pairs.csv`: 未登録Tx×申告IDごとの通過率。これは元のOpenMaxによる「いずれかの既知IDへの通過率」と分母が異なる。
- `selection.json`・`feature_reference.npz`: testの読込前に保存する参照値。`run.json`に元モデル・分割・コード・入力のhashを残す。
